READY

The candidate is ready to merge and release

Every behavioral blocker, contract gap, and hardening item found by the audit has been implemented and exercised. Pull request #68 passed Black, mypy, Python 3.11, 3.12, and 3.13 on Linux, plus the full final-installer suite on Windows.

The product now matches the intended 1.x boundary: strict project config, reproducible inputs, multiple selected outputs, self-contained Windows installation, managed version dispatch, and enforceable publication preflight.

Release Blockers

RESOLVED P0Argument-bearing old pre_uninstall hooks

Implementation: the installer retrieves the old manifest's pre_uninstall property without PowerShell pipeline enumeration, preserving the outer command list and every argv item.

Verification: the automated Windows test now launches two final ExeWrap installers, upgrades 1.0 to 2.0, proves an argument-bearing old hook ran, verifies Installed Apps was updated, and uninstalls the result.

RESOLVED P0Embedded and standalone release integrity

Implementation: payload and manifest hashes are sealed when the installer is assembled. post_dist may create extra outputs or sign the installer, but changing either sealed input fails the build. Publication preflight independently compares the embedded payload byte-for-byte and the embedded manifest semantically with their published counterparts.

Verification: focused tests prove payload mutation, standalone/embedded payload disagreement, and standalone/embedded manifest disagreement are all rejected.

PROCEDUREExact-revision release gate

Implementation: the package and dogfood release version are 1.3.0, avoiding the already-published 1.2.0 identity. The workflow includes Linux coverage and a Windows job that launches final installer executables.

Verification: the complete candidate is committed in pull request #68. Its Linux, Windows, Black, and mypy checks all pass; publication still requires merging the reviewed PR and tagging that resulting audited commit.

Contract Gaps

RESOLVED P1post_install completion semantics

Implementation: payload placement, installed uninstall scripts, shortcuts, and Installed Apps registration now complete before post_install. A failing hook still rolls back the new files, shortcuts, and registration and restores a prior recognized install.

RESOLVED P1Shortcut target and icon validation

Implementation: build-time payload validation resolves each target and effective icon against the final remapped archive destinations. Unsafe paths and absent files fail before archive creation.

RESOLVED P1Configured Python paths for installer hooks

Implementation: final remapped interpreter locations are recorded in the installer manifest. Installer hooks prefer the configured venv and then bundled runtime, and packaging fails if an automatic .py hook has no included configured interpreter.

RESOLVED P1Mutable local Poetry dependencies

Implementation: mutable Poetry file and directory dependencies are rejected before pip runs. The error directs projects to a hashed package-index artifact or a Git dependency pinned to a full resolved commit.

Hardening After Blockers

RESOLVED P2Named output freshness

Implementation: app-builder validates each bounded named-output pickup and removes matching stale files before post_dist. Protected built-in outputs cannot be cleared through this mechanism.

RESOLVED P2Dist-directory payload boundary

Implementation: the configured dist directory is excluded from payload selection by default. installer.paths.include_dist: true is the deliberate opt-in, and an otherwise empty payload fails clearly.

RESOLVED P2Concurrent managed-version cache creation

Implementation: source refresh and each managed ref use cross-process file locks. New entries build in private sibling directories and are atomically promoted only after installation and manifest creation; failed staging trees are removed, including read-only Git files.

RESOLVED P2Final installer EXEs in Windows CI

Implementation: the workflow now has a windows-latest job running the complete suite. Its Windows-only tests build and launch final ZIP and 7z ExeWrap installers, exercise upgrade and uninstall, and verify the resulting filesystem and registry state.

Documentation and Deadwood

Documentation is synchronized. The active help, README, configuration reference, release pipeline, generated YAML, and schema agree on commands, fields, lifecycle order, output freshness, payload sealing, runtime selection, and cache behavior. Tests assert full schema-field coverage and snapshot the generated references.

No obvious legacy runtime subsystem remains in the importable 1.x package. The files under app_builder/assets are all active inputs: the config template, starter files, icon, ExeWrap launcher, and 7-Zip binaries. The app_builder_meta package is active version dispatch, not dead compatibility code. The 0.x bridge is deliberately isolated behind the explicit 0.x command.

The prior readiness audit is historical evidence and should remain clearly dated. Generated dist files are build output, not source. No duplicate help HTML remains outside docs/app-builder-help.html.
